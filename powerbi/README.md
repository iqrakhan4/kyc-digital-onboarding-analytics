# Power BI Dashboard

Everything needed to build the interactive dashboard on top of the project's aggregate outputs.

| File | Purpose |
|---|---|
| `README.md` | This build guide |
| [`dax_measures.md`](dax_measures.md) | All DAX measures, ready to paste |
| [`theme.json`](theme.json) | Colour theme matching the charts in `reports/figures/` |
| `screenshots/` | Dashboard screenshots for the main README (add after building) |

> **Honest status:** a `.pbix` file is a binary created inside Power BI Desktop, so it is not
> generated by this repository. This guide takes about **45-60 minutes** to follow. The measures
> and layout below were prepared and checked against the exported tables, but not executed in
> Power BI Desktop by the author, so use [section 5](#5-validate-the-numbers) to confirm them.
> Power BI Desktop runs on Windows only.

## Privacy: which data should the dashboard use?

The export is an **aggregated cube** (counts by date, hour, platform, status, source, stage, SDK
and duration band). It contains **no transaction identifiers**, but with real data it is still
confidential aggregate data.

| Goal | Use | Commit the `.pbix`? |
|---|---|---|
| Public portfolio piece | **Synthetic** export | Yes |
| Your private/real analysis | Real export | **No.** Name it `*_real.pbix` (git-ignored). Publish screenshots only if you are permitted to |

## 1. Generate the data

From the project root:

```bash
make export-powerbi          # synthetic data  -> data/processed/synthetic/powerbi/
make real                    # private data    -> data/processed/powerbi/
```

Either command writes these tables:

| File | Rows (typical) | Description |
|---|---:|---|
| `fact_onboarding.csv` | 13k (synthetic) / 41k (real) | Aggregated counts; the only large table |
| `dim_date.csv` | 31 | Calendar for the data period |
| `dim_status.csv` | 8 | Status label, outcome group, approved/declined/manual flags |
| `dim_platform.csv` | 7 | Platform label, `is_known_platform` flag |
| `dim_stage.csv` | 9 | Stage with display order (the order is an assumption) |
| `dataset_overlap.csv` | 30 | Real run only: ID-overlap % between extracts (both directions) |

The export verifies that the fact table totals equal the source totals before writing.

## 2. Load the data

1. Open **Power BI Desktop**: **Home > Get data > Text/CSV**.
2. Browse to the export folder. From Windows, a WSL path looks like
   `\\wsl$\Ubuntu\home\<your-user>\kyc-digital-onboarding-analytics\data\processed\synthetic\powerbi\`
   (use your distro name; or copy the folder to a normal Windows folder first).
3. Load every CSV. In **Transform data**, confirm these types, then **Close & Apply**:

| Table | Column | Type |
|---|---|---|
| fact_onboarding | created_date | Date |
| fact_onboarding | created_hour | Whole number |
| fact_onboarding | transactions, time_spent_count | Whole number |
| fact_onboarding | time_spent_sum_seconds | Decimal number |
| dim_date | date, week_start | Date |
| dim_date | weekday_number, day_of_month, is_weekend | Whole number |
| dim_status | outcome_order, is_approved, is_declined, is_manual | Whole number |
| dim_platform | is_known_platform | Whole number |
| dim_stage | stage_order | Whole number |

## 3. Build the model

**Model view > Manage relationships.** Create four many-to-one relationships, **single direction**
(dimension filters fact):

| From (many) | To (one) |
|---|---|
| fact_onboarding[created_date] | dim_date[date] |
| fact_onboarding[status] | dim_status[status] |
| fact_onboarding[platform] | dim_platform[platform] |
| fact_onboarding[stage] | dim_stage[stage] |

Leave `dataset_overlap` **unrelated** (it is a standalone table for page 4).

Then:

1. **dim_date > Table tools > Mark as date table** using `date`.
2. **Sort by column:**
   - `dim_stage[stage]` sorted by `stage_order`
   - `dim_status[status_label]` sorted by `outcome_order`
   - `dim_date[weekday]` sorted by `weekday_number`
3. **Hide** from Report view: `fact_onboarding[transactions]`, `time_spent_sum_seconds`,
   `time_spent_count` (users should use measures), and the key columns used in relationships.
4. **View > Themes > Browse for themes** and select [`theme.json`](theme.json).
5. Create the `_Measures` table and add every measure from [`dax_measures.md`](dax_measures.md).

## 4. Build the report pages

Use a 16:9 canvas. Titles should state the finding, as in the README charts.

### Page 1: Executive overview

| Visual | Type | Fields |
|---|---|---|
| Five KPI cards | Card | `Total Attempts`, `Approval Share`, `Approval Rate (Decided)`, `Cancellation Share`, `No Decision Share` |
| Outcomes | Clustered bar | Axis `dim_status[status_label]`, Values `Total Attempts`, Legend `dim_status[outcome_group]` |
| Daily volume | Stacked column | Axis `dim_date[date]`, Values `Total Attempts`, Legend `dim_status[outcome_group]` |
| Slicers | Slicer | `dim_date[date]` (between), `dim_platform[platform_label]` |

### Page 2: Drop-off and platform

| Visual | Type | Fields |
|---|---|---|
| Where users cancel | Clustered bar | Axis `dim_stage[stage]`, Values `Cancelled` and `Cancellation Share by Stage` (data labels) |
| Cancellation rate by platform | Clustered bar | Axis `dim_platform[platform_label]`, Values `Finished Cancellation Rate`. **Visual filter:** `dim_platform[is_known_platform]` = 1 |
| Where each platform cancels | 100% stacked bar | Axis `dim_platform[platform_label]`, Legend `dim_stage[stage]`, Values `Cancelled`. Same visual filter |
| Slicer | Slicer | `fact_onboarding[sdk_version]` |

Add a text box: *"Platform differences are associations; this data cannot separate device mix,
SDK version and user population."*

### Page 3: Timing and volume patterns

| Visual | Type | Fields |
|---|---|---|
| Activity heatmap | Matrix | Rows `dim_date[weekday]`, Columns `fact_onboarding[created_hour]`, Values `Avg Attempts per Day`. **Format > Cell elements > Background color > Gradient** (min `#EEF3F8`, max `#1F5F8B`) |
| Journey duration | Clustered column | Axis `fact_onboarding[duration_band]`, Values `Total Attempts`, Legend `dim_status[outcome_group]`. Filter out `0. no duration recorded` |
| Average journey | Table | `dim_status[status_label]`, `Avg Journey (min)` |
| Volume trend | Line | Axis `dim_date[date]`, Values `Total Attempts`, `Attempts 7-Day Avg` |

### Page 4: Data quality and reconciliation (real data only)

| Visual | Type | Fields |
|---|---|---|
| Overlap heatmap | Matrix | Rows `dataset_overlap[row_dataset]`, Columns `dataset_overlap[column_dataset]`, Values `pct_of_row_ids_in_column` (Don't summarize / Maximum) with gradient background |
| Notes | Text box | "Overlapping extracts must not be summed. One extract is a 100% subset of another; the document-verification extract is probably truncated at 1,048,575 rows." |

Skip this page if you built from synthetic data.

## 5. Validate the numbers

Compare dashboard values against the CSVs the pipeline wrote (in `data/processed/` for real data,
`data/processed/synthetic/` for synthetic). They should match exactly.

| Dashboard | Compare with |
|---|---|
| `Total Attempts` (no filters) | `onboarding_kpi_summary.csv` > `total_transactions` |
| `Approval Share` | `approval_share_all_transactions` |
| `Approval Rate (Decided)` | `approval_rate_among_decided` |
| `Cancellation Share` | `cancellation_share_all_transactions` |
| `Finished Cancellation Rate` by platform | `platform_cancellation_summary.csv` > `cancellation_rate` |
| `Cancelled` by stage | `stage_dropoff_summary.csv` > `transactions` |
| `Manual Review Share` | `manual_review_summary.csv` (sum of `pct_of_all_transactions`) |

If a number differs, check (in order): relationship directions, the platform visual filter,
and whether a slicer is still active.

## 6. Finish

1. **Save** as `powerbi/KYC_Onboarding_Dashboard_synthetic.pbix` (or `*_real.pbix`, git-ignored).
2. Export each page as an image (**File > Export > Export to PDF**, or screenshot) into
   `powerbi/screenshots/` and link them from the main `README.md`.
3. Run `make check-privacy` before committing.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| All measures show the grand total | Relationship missing or inactive |
| Stage / weekday axes appear alphabetically | Sort-by-column not set (section 3) |
| `Attempts 7-Day Avg` errors | `dim_date` not marked as a date table |
| Platform chart includes "Not recorded" | Visual filter `is_known_platform = 1` missing |
| Heatmap shows 0 or blank cells | Hour is on the matrix columns but `created_hour` has no row for that slot; this is expected for quiet hours |
